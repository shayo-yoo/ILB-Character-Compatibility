# ADR-0004：导入冲突默认不覆盖

- 状态：已采纳（2026-11-02）
- 关联需求：需求 §6.2「默认禁止静默覆盖」、§6.1（不传 preserved_name）

## 背景

导入一个包时，目标 ILB 里可能已经有同一本书（同 `book_id`），酒馆里也可能已经有同名角色卡。
覆盖是不可逆的：用户可能在原书里改过条目、在原卡里改过设定。

## 可选方案

1. 一律覆盖（"导入就是我要最新的"）——会静默吃掉别人的改动
2. 一律跳过——用户想更新时没法更新
3. 默认最保守，冲突逐本让用户选

## 决定

采用方案 3：

| 冲突 | 默认 | 可选 |
| --- | --- | --- |
| 同 `book_id` 的书 | `skip`（用已有的，不导入） | `overwrite` / `create`（新建一本重名的） |
| 同名不同 id 的书 | `create`（新建，允许重名） | `reuse`（不导入，直接关联已有的那本） |
| 同名角色卡 | 新建（酒馆自动加后缀） | —（不提供覆盖，因为无法回滚） |

角色卡导入**不传** `preserved_name`：传了它酒馆会覆盖同名卡，这是最危险的一条路径。

## 原因

- 覆盖是"用户没看见就已经发生"的破坏；跳过只是"这次没生效"，两者代价不对称
- 逐本选择让"我要更新这本书"仍然可做，但必须显式点
- 角色卡不覆盖，符合"卡归酒馆管、本扩展不替用户做破坏性决定"

## 影响

- 重复导入同一个包会得到"书跳过、卡新建一张"的结果（预期；诊断页会显示同名卡数量）
- 界面必须把冲突书单独列出来，否则默认值会让人困惑（已实现：下拉框 + 徽标）

## 约束与重新审视条件

- 若用户反馈"每次都要手点"，可考虑加"本次全部按某策略处理"的批量选项（但默认值不变）
