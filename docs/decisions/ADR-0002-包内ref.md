# ADR-0002：包里的关联只引用包内 ref，不引用导出端的 book_id

- 状态：已采纳（2026-11-02）
- 关联需求：需求 §4「关联用稳定 ID 不用显示名」、审计 §6.5

## 背景

导出时每本书都有自己的 `book_id`。导入时如果目标 ILB 里已经存在同 id 的书，ILB 的处理是
按冲突策略决定的：`skip` 用已有的、`overwrite` 覆盖、`new` **生成一个新 id**。

也就是说：导入后的 `book_id` 和包里的 `book_id` 不保证相同。关联如果直接写死 `book_id`，
在 `new` 策略下必然指向一本不存在的书。

## 可选方案

1. 关联直接存 `book_id`（实现最省事，`new` 策略下会断）
2. 关联存书的名字（重名就错）
3. 包里给每本书一个本地 `ref`，关联指向 `ref`；导入时用 `ref → 新 id` 的映射重写

## 决定

采用方案 3。

- `worldbooks[].ref` 由导出时生成（默认取 book_id，重复时加序号）
- `bindings[].book_ref` 只指向包内的 ref
- 导入时以 `result.books.map[ref] = 实际 id` 建立映射，再建关联

## 原因

- 与"书导入后可能换 id"这个事实对齐；`skip` / `overwrite` / `new` / 复用同名书都能正确接上
- `ref` 只活在包内部，不需要全局唯一，也不受重名影响

## 影响

- 包格式多一层间接；读包的人不能直接把 `book_ref` 当 `book_id` 用
- 校验时必须检查 `book_ref` 在包内存在（已实现：`validatePackage`）

## 约束与重新审视条件

- 若将来包格式要支持"关联到包外已有的书"，需要给 `book_ref` 加 `external: true` 之类的标记
