# ADR-0003：导入先书后卡，书没导完不导卡

- 状态：已采纳（2026-11-02）
- 关联需求：需求 §6「先导书后导卡」、§6.3 部分成功

## 背景

酒馆的角色卡导入接口（`POST /api/characters/import`）没有"撤销"：一旦落库，只能由用户手动删除，
而且删除会连带聊天目录。世界书导入则是 ILB 内部数据，可以重试、可以删。

如果先导卡后导书：书失败时，用户会得到一张"忘了带书"的卡，而且关联无从建立；
如果先导书后导卡：书失败时最多留下几本多出来的书，删掉即可，角色卡不受影响。

## 决定

1. 先逐本导书；任何一本失败 → **停止**，不导入角色卡
2. 书全部成功后再导卡
3. 卡成功后，用真实 avatar + 真实 book id 建关联
4. 结果里必须分列：书成功/跳过/复用/失败、卡成功与否、关联成功/失败、可清理的书 id

## 原因

- 把"不可撤销"的动作放在最后，是唯一能保证"最坏情况只是多点垃圾"的顺序
- 失败必须看得见（需求 §6.3）：结果面板逐条列出，禁止"整体成功"糊过去

## 影响

- 一次导入可能产生"部分成功"状态；界面与历史记录都单独表达 `partial`
- 用户重试时会遇到"书已存在"的冲突，这是预期行为（默认 skip）

## 约束与重新审视条件

- 若酒馆将来提供"删除角色卡并回滚"的接口，可以重新考虑并行导入
- 若发现卡导入失败率显著高于书（例如卡格式问题），顺序仍应保持：卡失败时书留着可手动关联
