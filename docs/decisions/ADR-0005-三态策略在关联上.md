# ADR-0005：三态策略落在关联记录上，不改书的 activation

- 状态：已采纳（2026-11-02）
- 关联需求：需求 §3.5、§6.5；ILB 决策记录 D-0087

## 背景

"这个角色要用这本书"有三种语义：跟随书自己的策略、强制启用、强制停用。
实现上有两种落点：改书本身的 `activation.strategy/override`，或者写在关联记录上。

改书是全局的——A 角色强制启用这本书，会把 B 角色的行为也一起改掉；而需求恰恰要求
"多卡共享一本书、各自策略不同"。

## 决定

策略存在关联记录的 `policy` 字段（`auto` / `on` / `off`），书本身的 `activation` 不动。

判定优先级（由 ILB 实现，本扩展只依赖它）：

1. 书 `override='off'` → 停
2. 书 `override='on'` → 启
3. 当前角色（群聊为成员）关联 `policy='off'` → 停
4. 关联 `policy='on'` → 启
5. 书 `strategy='always'` → 启
6. `strategy='auto'` 且（关联 `auto` 或原生匹配）→ 启
7. `strategy='manual'` → 按手动开关
8. 其余 → 停

## 原因

- 策略是"角色 × 书"这一对关系的属性，不是书的属性；放在关联上语义正确
- 与 ILB D-0087 一致：关联强制停用可以压过书的 `always`，但压不过书自己的 `override`
- 本扩展不需要（也无法）改书的 activation —— ILB 1.4 没有这个接口

## 影响

- 同一本书被多个角色关联时，各自的策略互不影响
- 界面上的"强制启用"只影响当前角色，这一点必须在提示里写清楚（已写在关联页底部）

## 约束与重新审视条件

- 若将来需要"角色组"级别的策略，需要 ILB 扩展 bindings 的维度（不在 v1 范围）
